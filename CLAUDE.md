The spec is `PRODUCT.md` (it is the contract; propose a change rather than diverge). Code, logs, error messages and docs in English.

## Commands

```bash
bun install
bun run dev          # server :8080 (DATA_DIR=.data, LOG_LEVEL=debug, --watch) + Vite :5173 (proxies /api and /health)
bun run dev:lan      # same, Vite reachable on the network: a real phone or tablet opens http://<mac-ip>:5173
bun lint             # Bun's linter (bunfig.toml [lint], canary): layers, no class, no null, confined try/catch (§5.3)
bun run typecheck    # bun check (strict) in each workspace + runtime/ (mobile: tsc emits the server's AppType first)
bun run test         # bun test on the whole repository (bun test <path> to target)
bun fmt              # Bun's native formatter (bunfig.toml [fmt]); bun fmt --check in CI
bun run db:generate  # Drizzle migration from the schema (see below)
bun run build:web    # apps/web/dist, served by the server with SPA fallback
bun run dev:www      # public website (apps/www) on :5175; build:www → apps/www/dist (static)
bun run build:bundle # dist/app/: server.js + public/ + drizzle/ + manifest.json (runtime/README.md)
bun run e2e          # Playwright on the bundle, one server: every journey on Chromium, @webkit/@mobile smoke on WebKit (e2e/)
bun run --cwd apps/desktop fetch-libmpv  # LGPL libmpv, pinned + SHA-256: Windows libmpv-2.dll (zhongfly/mpv-winbuild) → src-tauri/lib/; macOS arm64 libmpv.dylib + 17 deps (media-kit/libmpv-darwin-build) → src-tauri/lib/macos/
bun run --cwd apps/desktop build:web     # the desktop's bundled UI (Vite) → apps/desktop/web/dist (Tauri's frontendDist)
bun run --cwd apps/desktop dev           # desktop app (§28, Windows and macOS): builds the UI, then a Tauri dev window; needs Rust and fetch-libmpv
bun run --cwd apps/desktop build         # release exe + Windows installer, or macOS projo.app + .dmg (ad hoc signed), UI and libmpv bundled
```

Desktop (§28): Rust stable and the Tauri 2 prerequisites (WebView2, MSVC build tools; on macOS the Xcode command line tools, §28.11; `fetch-libmpv` on either). `CARGO_TARGET_DIR` is `C:\t` on Léo's Windows machine. `cargo test` in `apps/desktop/src-tauri` runs the Rust unit tests (not part of `bun run test`; CI runs them in the `desktop-build-windows` and `desktop-build-macos` jobs); `generate_context!` needs `web/dist`, so run `build:web` once before any `cargo build`. No Vite dev server for the desktop: the page must be on `http://tauri.localhost` (the origin the server's CORS allows), so `dev` builds the UI once (rerun `build:web` and restart to see a change). A debug build exposes the page over CDP on `127.0.0.1:9229` (`--remote-debugging-port`): that is how a script drives it.

Pinned versions (`bunfig.toml`: `exact = true`). Bun: the dated canary of `packageManager`, because `bun lint` does not exist in stable (1.4.4); install it with `bun upgrade --canary` or `npm i -g bun@<version>` (what CI does). The `lint` script first checks that `bun --help` lists `lint`: a stable Bun fails with a message instead of rerunning the script in a loop. The runtime image (`runtime/Dockerfile`) stays on 1.4.4 stable. No native dependency on the server: the app is a pure JS bundle (auto-update, §16).

## Rules (§5.3), checked by lint

- **Layers**: `core` → `@projo/shared` only (no package, no `node:`/`bun:`); `application` → `core`; `infrastructure` → `core`; `entrypoints` → everything. Tests follow the rules of their folder: test doubles in `apps/server/test/support/`, not in `infrastructure/`.
- **Apps never import each other** (web, www, mobile, desktop; no `../web/src/…`): what two apps share goes in a package (`@projo/design`, `@projo/i18n`, `@projo/player`, `@projo/shared`, `@projo/web-app`). Packages never import an app.
- **Player layers** (§5.3 "Layers of the player"): `packages/player/**` imports only relative paths, `@projo/shared` and `bun:test` (`no-restricted-imports` override): no DOM, no `fetch`/`window`/`document`, no React or React Native, and Hermes-safe (no `Intl.DisplayNames`/`Intl.Locale`/`Intl.RelativeTimeFormat`, no `toSorted`). Zones (`import/no-restricted-paths`): `packages/player/src/core` ↛ `src/application`; `packages/player` ↛ `apps/`; `packages/web-app` ↛ `apps/`; `packages/web-app/src/features/player/ui` ↛ `engines/`; `engines/mpv` and `engines/html-video` never import each other. `src/testing/` is for tests only. The UI decides on `EngineCapabilities`, never on an engine's name; the host picks the engine (`AppHost.playerEngine`), asked only through `features/player/player-engine.ts` (by the player routes: `player-route.tsx`, `live-player-route.tsx`).
- **Hosts of the web app** (§5.2): everything that differs between the browser and the desktop app goes through `AppHost` (`packages/web-app/src/host.ts`); the package never tests which host it runs in (no `__TAURI_INTERNALS__`, no `window.location.origin` for the server: `serverOrigin` / `useServerAddress()`), never builds a server URL a page loads by itself without `mediaUrl()` (`shared/api/media.ts`: origin + media key, §20), never calls `fetch` on the server without `serverFetch`/`api`. Module-level pieces read the host bound by `mountApp` (`shared/host/bound-host.ts`). Zones: the package's default paths ↛ `src/desktop/` and `engines/mpv/` (reached only through their exports); `apps/web` ↛ both (zone + `no-restricted-imports`), so the browser entry chunk has no Tauri or mpv code; the one exception is the transitional `apps/web/src/desktop-compat/` (its own lazy chunk, `@projo/web-app/desktop/*` only, never mpv), removed once desktop apps older than the bundled-UI release are gone, together with the `projo-desktop` row of `apps/server/src/core/auth/user-agent.ts`.
- **Curried factories**, no container: `const xFactory = ({ deps }: XDeps) => (input) => …`. Ports = object types of functions.
- **No class, no `null`** (neither literal nor type). `null` allowed only in `infrastructure/sqlite/`, converted at the boundary (`stripNulls`, `toNullable`, `fromIso` in `sqlite/rows.ts`). Optional properties `x?: T` (with `exactOptionalPropertyTypes`, build with `...(v === undefined ? {} : { x: v })`).
- **`Result` for every expected failure** (`ok, err, map, mapError, andThen, match, all, fromPromise, unwrapOr` from `@projo/shared`). `throw` = bug or violated invariant. **`try/catch` only in `infrastructure/`**; elsewhere `fromPromise(() => …, toError)`.
- **Errors**: `appError('domain/reason', 'english message', { context, cause })`. Each use case declares its union: `type RenameLibraryError = AppError<'library/not_found' | 'library/name_taken'>`. The `context` goes to the client (never the `cause`); outside `/api/v1/admin/*`, `respondError` strips the `*path`/`stderr` keys and absolute paths from it (§20).
- **Zod validation at the boundaries**: HTTP input (`validate`), job payload (`defineJobHandlers`), JSON column (`parseJsonColumn`), external API response.
- **Synchronous** SQLite repositories (`bun:sqlite`): `.get()`, `.all()`, `.run()`, `db.transaction((tx) => …)` for a transaction internal to one adapter. A `transaction` a repository offers to use cases (port type `Transaction` of `core/transaction.ts`, synchronous callback only) goes through `transaction(db, run)` of `infrastructure/sqlite/transactions.ts`: events published inside are delivered after the outermost commit and dropped on rollback (deferring inside a plain top-level `db.transaction` throws). Any other side effect a use case may trigger inside one (stopping ffmpeg, clearing an in-memory cache) goes through `platform.afterCommit` (`AfterCommit` port: runs at once outside a transaction). ISO UTC dates in the database, `Date` in the domain. Ids: `ids.next()` (UUID v7).
- **One use case per file**: `application/<domain>/<verb-noun>.ts` exports `<verbNoun>Factory`, `type <VerbNoun> = ReturnType<…>` and, when it can fail, `<VerbNoun>Error`; its test sits beside it. No factory returning an object of several use cases, no `types.ts` restating signatures, no barrel, no `utils.ts`: helpers shared within a domain go in `application/<domain>/shared/<what-it-is>.ts` and must not import a top-level use-case file. Routes and modules receive use cases one by one (`adminItemsRoutes({ searchTmdb, rematchItem, … })`); an admin settings section is a `{ get, update }` pair built in its module. Exception: a component whose methods share in-memory state stays whole, named after what it holds (`playback/hls-streams.ts`, `playback/home-previews.ts`, `playback/transcode-slots.ts`, `tv/live-streams.ts`, `metadata/shared/resolve-match.ts` series cache, `profile/visibility-scope.ts`, `updates/update-state-holder.ts`, `operations/measure-storage.ts`, `scanner/library-watchers.ts`); build it once in its module.
- **Narrow ports**: a use case declares only what it uses (`Pick<CatalogReadModel, 'search'>`), and names the dependency after the port (`visibleItems`, `catalogReadModel`, `playableSources`, not `catalogRepository`).

## Full example: renaming a library

```ts
// core/library/library.ts — type + port
export type Library = { id: string; name: string; createdAt: Date; metadataLanguage?: string }
export type LibraryRepository = {
  findById: (id: string) => Library | undefined
  findByName: (name: string) => Library | undefined
  rename: (input: { id: string; name: string }) => Library
}

// application/library/rename-library.ts — use case
type Deps = { libraryRepository: LibraryRepository; logger: Logger }
export type RenameLibraryError = AppError<'library/not_found' | 'library/name_taken'>
export const renameLibraryFactory =
  ({ libraryRepository, logger }: Deps) =>
  async ({
    id,
    name,
  }: {
    id: string
    name: string
  }): Promise<Result<Library, RenameLibraryError>> => {
    if (libraryRepository.findById(id) === undefined)
      return err(appError('library/not_found', 'library not found', { context: { id } }))
    if (libraryRepository.findByName(name) !== undefined)
      return err(appError('library/name_taken', 'library name already used', { context: { name } }))
    logger.info('library renamed', { libraryId: id })
    return ok(libraryRepository.rename({ id, name }))
  }

// infrastructure/sqlite/library-repository.ts — adapter
const toLibrary = (row: typeof libraries.$inferSelect): Library => {
  const { id, name, createdAt, metadataLanguage } = stripNulls(row)
  return {
    id,
    name,
    createdAt: fromIso(createdAt),
    ...(metadataLanguage === undefined ? {} : { metadataLanguage }),
  }
}
export const createSqliteLibraryRepository = ({ db }: { db: Db }): LibraryRepository => ({
  findById: (id) => {
    const row = db.select().from(libraries).where(eq(libraries.id, id)).get()
    return row && toLibrary(row)
  },
  // …
})

// entrypoints/http/routes/admin-libraries.ts — route (mounted under /api/v1/admin)
export const adminLibrariesRoutes = ({
  renameLibrary,
}: {
  renameLibrary: ReturnType<typeof renameLibraryFactory>
}) =>
  new Hono<AppEnv>().patch(
    '/libraries/:id',
    validate('json', renameLibraryBodySchema),
    async (c) => {
      const result = await renameLibrary({ id: c.req.param('id'), name: c.req.valid('json').name })
      return result.ok ? c.json(toLibraryDto(result.value), 200) : respondError(c, result.error)
    },
  )

// entrypoints/modules/libraries.ts — wiring
export const buildLibrariesModule = ({ db, logger }: Platform) => {
  const libraryRepository = createSqliteLibraryRepository({ db })
  return defineModule({
    exposes: {
      routes: adminLibrariesRoutes({
        renameLibrary: renameLibraryFactory({ libraryRepository, logger }),
      }),
    },
  })
}

// application/library/rename-library.test.ts — unit test, in-memory adapter
test('refuses a taken name', async () => {
  const rename = renameLibraryFactory({
    libraryRepository: inMemoryLibraries([a, b]),
    logger: silentLogger,
  })
  expect(await rename({ id: a.id, name: b.name })).toMatchObject({
    ok: false,
    error: { code: 'library/name_taken' },
  })
})
```

Chain Hono methods (`new Hono<AppEnv>().get(…).post(…)`): that is what gives the RPC type. The Zod schema of the body lives in `packages/shared/api/libraries.ts` (shared with the web).

## Migrations

1. Edit `infrastructure/sqlite/schema/<group>.ts` (`casing: 'snake_case'`: camelCase properties → snake_case columns; booleans `integer({ mode: 'boolean' })`, dates ISO `text()`, JSON `text({ mode: 'json' }).$type<unknown>()` validated by `parseJsonColumn`).
2. `bun run --cwd apps/server db:generate --name <what>` → new `drizzle/NNNN_<what>.sql` + `meta/`. Never edit an existing migration. Agents in parallel: one generation at a time, check `drizzle/meta/_journal.json`.
3. Applied on startup (`openDatabase`), with a `VACUUM INTO` copy in `/data/db/backups/` if the database exists and migrations are pending (the last two `*-pre-migration.db` are kept). Failure ⇒ the process exits with code 1.

Since the end of M1, migrations are **additive**: no more merging and no more regenerating `0000_init` (Léo has a real database in `.data/`). SQL Drizzle cannot express (FTS5 virtual tables, triggers): `db:generate --custom --name <what>` then write the SQL in the created file.
